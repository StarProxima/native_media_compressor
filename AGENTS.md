# AGENTS.md

Правила работы в репозитории для кодовых агентов (Claude Code, Codex, Cursor) и людей.

`native_media_compressor` - Flutter-плагин для pub.dev: сжимает картинки и видео системными кодеками платформы (MediaCodec, AVFoundation и ImageIO, Media Foundation и WIC, GStreamer и gdk-pixbuf, WebCodecs и canvas). Своих кодеков и ffmpeg в пакете нет и не будет: вес пакета - только его собственный код.

## Публичность

Репозиторий публичный, пакет публикуется на pub.dev. Ни в коде, ни в тестах, ни в документации, ни в коммитах и PR не упоминаются приложения, компании, внутренние тикеты и инфраструктура, где пакет используется. Примеры и тестовые данные - нейтральные.

## Язык

- README, CHANGELOG, dartdoc, комментарии в коде, сообщения об ошибках - на английском: это читают пользователи пакета.
- Описания PR, ответы в ревью, обсуждения - на русском.
- Описание в заголовке коммита - на английском, lowercase.

## Коммиты

Формат заголовка: `Emoji [type]: краткое описание` - 1-6 слов, английский, lowercase, без точки, отвечает на "что и зачем".

| Type | Emoji | | Type | Emoji |
|---|---|---|---|---|
| feat | ✨ | | test | ✅ |
| fix | 🐛 | | perf | ⚡️ |
| chore | 🔧 | | ci | 👷 |
| refactor | ♻️ | | build | 📦 |
| docs | 📝 | | release | 🚀 |
| style | 🎨 | | | |

Если причина изменения не видна из диффа - тело коммита через пустую строку, коротко "зачем". Логически разные изменения - разными коммитами. Никаких `Co-Authored-By` и других трейлеров соавторов.

## Ветки и PR

- Любое изменение идёт через PR в `main`, прямых пушей в `main` нет.
- Имя ветки описывает работу: `<type>/<slug>` (`feat/linux-gstreamer`). Подпись агентом (`claude/...`, `codex/...`) в именах веток, коммитах и PR запрещена.
- Заголовок PR в формате коммита. Описание - для холодного читателя: сначала зачем, потом что сделано, затем как проверено и что не проверено.
- Перед тем как звать человека, PR проходит ревью панелью агентов разных моделей, находки триажатся и чинятся отдельными коммитами.
- Мерж - обычный merge commit, без squash и rebase. Мержит человек.

## Устройство

- `lib/` - публичный Dart API (`NativeMediaCompressor`), платформенный интерфейс и web-реализация.
- `pigeons/messages.dart` - схема канала к нативу; сгенерированные `*.g.*` не правятся руками, перегенерация: `dart run pigeon --input pigeons/messages.dart && dart format lib/src/messages.g.dart` (pub.dev снижает оценку за неотформатированный Dart).
- `android/` (Kotlin), `darwin/` (Swift, общий для iOS и macOS), `windows/` (C++), `linux/` (C++ на GObject) - нативные реализации.
- `example/` - пример и integration-тесты (`example/integration_test/`) на реальных образцах из `example/integration_test/fixtures/`.

Решения "что сжимать" (пороги, правило принятия результата) - забота приложения. Пакет даёт операции: сжать видео, сжать картинку, прочитать параметры картинки и видео без раскрытия.

## Поведение, которое нельзя ломать

- Любая неудача - не исключение и не потеря файла: операция возвращает исход (`unsupported`, `failed`, `tooLarge`, `cancelled`, `interrupted`). Результат пишется во временный файл рядом и переезжает в `destination` только при `compressed`, поэтому при неудаче `destination` остаётся как был, а `destination == source` безопасно.
- Ничего не увеличивается: кадр и картинка только уменьшаются.
- Платформа без нужного кодека или системной библиотеки отвечает `unsupported`, а не падает (Windows N без Media Feature Pack, Linux без GStreamer).

## Проверка

Перед коммитом по затронутым частям:

1. `dart format .` и `flutter analyze` - без замечаний.
2. `flutter test` - юнит-тесты Dart.
3. Integration-тесты примера на платформах, чей код тронут: `cd example && flutter test integration_test -d <device>`. CI гоняет их матрицей на Android, iOS, macOS, Windows, Linux и web.

Комментарии в коде - только "зачем", не "что": неочевидное ограничение платформы, порядок вызовов, причина выбора. Пересказ кода и история правок - нет.
